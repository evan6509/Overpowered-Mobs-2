# Bug fixes from the October 1, 2026 audit

Audit basis: commit `9a8ab4007b5ff2bfeaf5b5f8efb76d08a654d6ac`, Fabric / Minecraft 26.2. These changes address the 17 reported findings.

| Finding | Resulting behavior |
| --- | --- |
| 1. Malformed config destroys settings | Invalid files are preserved. Failed reloads keep the active config and report failure; startup can use defaults in memory. Saves replace the file atomically where supported. |
| 2. Cave spiders bypass initialization | Monster initialization runs on the first server tick, including species whose spawn override never calls the base method. |
| 3. Subclasses overwrite boosted attributes | Stats run after complete vanilla spawn initialization. Permanent modifiers keep boost and elite scaling when size-based attributes are reset or saved/reloaded. |
| 4. Conversion/splitting lose boosts | Completed conversions reapply the source's boosted, elite, or horde tier to the new species. Living conversions retain the source's health percentage; split children start at full health. |
| 5. Ranged/special damage ignores multipliers | Mob-owned projectiles, evoker fangs and sonic booms scale at the victim's damage entry point. The separate arrow hook is removed so arrows scale once. Player attacks and ordinary melee bypass this hook. |
| 6. Illusioners lose their ranged attack | The default weapon for illusioners is a bow. |
| 7. Distance speed cancels configured speeds/effects | Distance acceleration is relative to the species' vanilla reference attribute. Stat multipliers and potion effects remain active. |
| 8. Elite equipment is not preserved loot | Elite equipment uses Minecraft's preserved drop chance, including environmental deaths and intact durability. |
| 9. Unsafe cavalry/piñata positions | Cavalry checks both mount and projected rider space. Piñata children search for a supported, collision-free, dry position inside the world border. The cavalry command checks space too. |
| 10. Cavalry renderer depends on server-only tags | Client stabilization uses vanilla passenger links. It also stabilizes other mob-on-mob jockeys; server cavalry AI continues to use the mod's tag. |
| 11. Warden hearing misses sections | Events are delivered to boosted Wardens outside the sections vanilla visited, using vanilla vibration filtering and scheduling. No duplicate delivery is made to listeners in the original sections. |
| 12. World-generation wolves skip anger | Spawn anger no longer requires a direct `ServerLevel` argument. Player selection runs when a wild wolf ticks in the server world. |
| 13. Wolves lose permanent anger | Wild wolves maintain their anger through normal AI timer refreshes and select valid living players, excluding creative and spectator players. Tamed wolves are excluded. |
| 14. Untagged draft release breaks recovery | Version selection tolerates missing tags and safely resumes drafts targeting an exact commit. Mutable or unresolved drafts reserve their version. Draft lookup has the required permission only in the main-push version job; publication checks an untagged draft's target. |
| 15. Blood-moon sky flash is a no-op | Vanilla lightning spawn packets provide client flashes and thunder. Lightning is never added to the server world, so it cannot damage entities, start fires or change blocks. |
| 16. Ghast speed values below one are ignored | Fractional increments support slowdown while preventing repeated charge sounds and skipped firing thresholds. |
| 17. Creeper chain radius is a cube | A squared-distance check enforces the configured radius after the candidate lookup. |

## Validation

- Java 25 compilation passed.
- Isolated Fabric startup loaded all server Mixin targets, including the conversion, shared damage and Warden dispatch hooks. Startup stopped at the EULA check, before a world ran.
- A headless Fabric client probe transformed the cavalry renderer Mixin and exited before game startup.
- Ten config probe assertions passed, including malformed startup/reload preservation, retention of custom settings, reloadable saved JSON and temporary-file cleanup.
- Minecraft attribute probes confirmed multiplicative boost/elite modifiers, persistence through base-value resets, retained speed effects and preserved elite equipment semantics.
- Release probes covered an empty history, same-commit drafts, other-commit drafts, mutable draft targets, deleted published tags, ignored prereleases and published-commit reruns.
- Workflow YAML and embedded Bash syntax parsed successfully. Ghast arithmetic probes covered multipliers 0.1, 0.5, 1, 2, 2.5 and 100 without duplicate charge sounds or skipped shots.
- The full build and installable-JAR verification run after committing so the embedded build number corresponds to the committed source.

No test tasks or dependencies were added. In-world combat, collision outcomes, client visuals and live GitHub release execution still require gameplay/CI validation. Existing tagged mobs are not globally reprocessed; newly initialized mobs and subsequent conversions use the corrected behavior.

## Cavalry rotation follow-up

First-tick initialization belongs before mob AI, but the cavalry rotation lock must run after it. The initial fix accidentally moved both to the start of `Mob.tick`, allowing movement, look and body-rotation controllers to overwrite the lock. Cavalry synchronization now runs at the end of that method. Riders also inherit the mount's previous rotation, with yaw differences normalized to the shortest turn across the 180-degree boundary. Spawn initialization remains at the start of the tick.

The source ordering, transformed Mixin bytecode and rotation/interpolation probes are checked separately from visible gameplay. A real client/server session is still needed to confirm the reported spinning has stopped.
