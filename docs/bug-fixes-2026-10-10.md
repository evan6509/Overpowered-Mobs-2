# Bug fixes from the October 10, 2026 audit

Audit basis: commit `18287f6`, Fabric / Minecraft 26.2. Each of the eleven findings was assigned to a separate agent; integration received an additional independent review.

| Finding | Resulting behavior |
| --- | --- |
| 1. Fixed attacks ignore damage multipliers | Boosted creeper and wither explosions, Dragon contact/breath, Guardian magic/thorns, Ravager roar and the magma cube's fixed bonus now receive mob, dimension and elite damage multipliers. Attribute-based melee remains scaled once. |
| 2. Wolves remain permanently angry after disabling the option | The mod's infinite anger override is released on the next server AI tick when disabled or when a wolf is tamed. Idle wolves become calm; existing aggression uses vanilla's finite anger timer. Saved infinite overrides are covered. |
| 3. Cavalry chickens never despawn and lay eggs | Successful tagged chicken mounts receive vanilla's chicken-jockey flag. Saved tagged mounts are repaired when ticking, including orphaned mounts. Vanilla despawning and egg suppression apply; passenger mob-cap rules remain vanilla. |
| 4. Piñata lifetime resets on reload | A dedicated age counter persists across saves and mob conversion. Piñata mobs expire after 600 active server ticks in total; unloaded time pauses the counter. Older saves without an age start at zero once. |
| 5. Dragon XP ignores configured multipliers | Dragon death awards use the configured XP multiplier for both first and later kills. Ten bursts plus the final remainder add up to the exact rounded total. The selected total persists through mid-death reloads; vanilla timing and mob-loot guards remain in place. |
| 6. Ghast cavalry riders cannot hit ground targets | Tagged ghast-mounted wither skeletons extend their melee attack box down to the mount's underside. Vanilla horizontal reach, minimum weapon range and line-of-sight checks remain in place. |
| 7. Retrying an older release replaces Latest | Publication refreshes release history and explicitly keeps an older version from taking Latest from a newer published stable release. Drafts and prereleases do not block a newer stable release. |
| 8. Commands report success after failed saves | Saves return their result. `/opm set` and `/opm test` roll back active settings and report failure when saving fails. Inherited and explicit per-mob settings retain their original state. Missing-config creation failures are reported too. |
| 9. Failed reset claims defaults were restored | Reset writes normalized defaults before replacing the active config object. A failed write preserves the original file and active settings, and the command reports failure. Saves require atomic replacement; unsupported atomic moves fail safely instead of falling back to a potentially destructive replacement. |
| 10. Large fireball power overflows saved bytes | Explosion power saves as an integer and loads without rescaling. Powers above 127 survive reloads; existing byte-valued saves remain compatible. Previously overflowed negative values cannot be reconstructed from old saves. |
| 11. Deployment removes unrelated prefix-matching files | Cleanup removes only regular matching mod JARs, excluding sources JARs and the current artifact. Backups, JSON, directories, symlinks and unrelated mods are retained. |

## Validation

- Integrated Java 25 compilation passed. Isolated Fabric startup transformed all changed server targets: `Mob`, `Wolf`, `Ravager`, `MagmaCube`, `EnderDragon` and `LargeFireball`.
- A temporary Fabric probe executed the actual transformed persistence handlers with real Minecraft NBT. All 22 assertions passed, covering piñata save/reload/conversion, expiration at tick 600, legacy saves, age bounds, integer and legacy-byte fireballs, and Dragon XP remainder persistence.
- Targeted probes covered 32 damage-attribution cases, wolf anger restoration, chicken-jockey assignment, actual attack-box geometry, and 300,003 Dragon XP distribution cases.
- Config probes used the changed production config and extracted command methods with temporary stubs. They covered read-only directories, failed replacement, missing/malformed files, explicit/inherited override rollback, command feedback and temporary-file cleanup. A custom temporary filesystem provider rejected atomic moves and verified no fallback, no original-file damage and no active-config replacement.
- Release probes checked older/newer versions, ignored drafts/prereleases, exact-commit reuse, publication arguments, invalid history and API failure handling. Embedded shell syntax passed. No GitHub release was published.
- The exact deployment cleanup/copy code passed an isolated Groovy filesystem probe, including old/current JARs, backups, sources, unrelated files, directories and symlinks.
- Independent gameplay and config/release reviews found no remaining concrete defects after the atomic-save correction.

For the committed artifact, run `./gradlew --no-daemon --offline build --rerun-tasks` and `python3 scripts/verify_mod_jar.py build/libs`. Build numbering comes from the committed Git history.

No permanent test tasks or dependencies were added. Startup stopped at the EULA check before running a world. The runtime probe calls transformed handlers using allocated entities; it does not exercise world AI, combat, collisions or a connected client. Gameplay and live GitHub release execution remain separate validation steps.
